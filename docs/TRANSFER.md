# Transfer Manifest — everything added to build this project

A running list of every install and artifact, so this project can be rebuilt on
another machine. Kept up to date as the project grows. See the README's "Moving
this project" section for the short version.

Last updated: Phase 7 (2026-07-27). DB driver switched from psycopg (LGPL) to
pg8000 (BSD-3-Clause) to satisfy the "no copyleft" requirement; `pip-audit`
installed as a dev tool.

---

## 1. Machine-level installs (NOT inside the project folder)

These live outside `BMS-Cloud-Dashboard/` and must be reinstalled on the new
machine.

### System software (installed via `winget`, user scope, no admin)
| Package | winget id | Version | Notes |
|---|---|---|---|
| PostgreSQL | `PostgreSQL.PostgreSQL.17` | 17.10 | Windows service `postgresql-x64-17`, port 5432. `psql` at `C:\Program Files\PostgreSQL\17\bin`. Superuser `postgres` / password `postgres`. |
| Node.js LTS | `OpenJS.NodeJS.LTS` | 24.18.0 | ships npm 11.16. Needed a new shell for PATH. |

Python was already present: `py` launcher → Anaconda Python 3.12.4.

### Python packages (global, via `py -m pip install`)
Captured in `backend/requirements.txt` and `simulator/requirements.txt`:
- `pg8000` ≥ 1.31 (BSD-3-Clause — permissive Postgres driver)
- `fastapi` 0.140.0
- `uvicorn[standard]`
- `python-dotenv`

Dev-only tool (NOT a project dependency, not in requirements): `pip-audit`.
The earlier `psycopg`/`psycopg_pool` packages are no longer used and can be
ignored (LGPL — replaced by pg8000).

> On the new machine, prefer a project virtualenv:
> `py -m venv .venv` → activate → `pip install -r backend/requirements.txt -r simulator/requirements.txt`

### Node packages (in `frontend/node_modules/`, git-ignored, regenerated by `npm install`)
Declared in `frontend/package.json`:
- runtime: `react` ^18.3, `react-dom` ^18.3, `recharts` ^2.13
- dev: `vite` ^7.0 (resolved 7.3.6), `@vitejs/plugin-react` ^4.6
- `npm audit`: **0 vulnerabilities**
